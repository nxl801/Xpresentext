# Xpresentext 自由讲解 · Laya 实测

2026-11-22。**本轮决定：暂缓将 Laya 接入自动置灰。** 英文模型能识别跨句和部分乱序改述。中文模型有把未表达的结论标成已讲的实测反例。仅依靠调高或调低一个分数，两种语言都无法在这组输入上同时做到可靠识别和保留遗漏。

## 测了什么

- **英文。** 用个人 Mac 的浏览器在本机运行英文 Laya 的 422 MB 分块 INT8 ONNX 版本，后端为 WASM。前 14 段发言各对照 3 个要点，另外 8 段检验新说法。再加 9 组全新要点和发言，检查百分比、变化方向、将来目标及缺少基线。全套语义推断共 75 对，其中应灰 18 对、应白 57 对。14 段基础样本和 8 段新增样本共用 3 条讲稿要点，两组并非来自独立胶片。[模型移植与运行页面](https://github.com/vishalmysore/layaForWeb)
- **中文及中英混讲。** 通过公开演示服务对原版 322M 多语言权重做了 12 对判断，含 5 对应灰、7 对应白。混讲的同一段发言分别核对了两个讲到的主张和一个遗漏的主张。输入均为本次编写的虚构发言，未使用个人录音或真实胶片。演示服务将输入放入四个消息字段，随内置问题一起运行，因此该结果对应这个输入格式。[原版权重](https://huggingface.co/convaiinnovations/laya-multilingual) · [演示程序与请求格式](https://huggingface.co/spaces/abhishekbhakat/laya-multilingual-demo/blob/main/app.py)
- 已知目标要点直接送给模型。现场还要从更多要点中找到候选，这一步可能追加漏判。本次测量止于模型对文本的判断，没有采集麦克风、接入 Apple 或 Whisper，或测量整场演讲的翻页和颜色状态。

## 结果

「应灰且命中」表示要点已说完整且被模型认出。「误灰」表示原本应该提醒演讲者的遗漏会被隐藏。评分按页面展示的四舍五入值统计。除四级评分以外，表内统一以肯定选项的概率 ≥ 0.80 作比较，并非经过校准的产品阈值。

| 运行方式 | 应灰且命中 | 漏掉已讲 | 误灰 / 应白 |
|---|---:|---:|---:|
| 英文，通用四级评分，≥ 2.00，基础集 | 10/10 | 0 | 28/32 |
| 英文，为每个要点手写三个具体备选，基础 + 新说法 | 9/15 | 6 | 0/51 |
| 英文，通用语义推断，基础集 | 7/10 | 3 | 0/32 |
| 英文，通用语义推断，新说法 | 2/5 | 3 | 0/19 |
| 英文，通用语义推断，全新要点 | 1/3 | 2 | 0/6 |
| 中文 / 混讲，给每个要点提供三个具体备选 | 1/5 | 4 | 1/7 |
| 中文 / 混讲，发言与假设成对输入，选择推断关系 | 3/5 | 2 | 7/7 |

**阈值能改善多少？** 英文语义推断在 0.80 时共认出 10/18，误灰 0/57。回看数据将阈值降至 0.70，可认出 12/18，误灰仍为 0/57。样本中最高的反例为 0.679，所有高于这一分数的正例也只有 12 个。这是观察完结果后的上限估计，不能视为独立验证。中文具体选项的完整肯定句得 0.817，只有前半句的反例反而得 0.929。

| 实际说法 | 演讲者应该看到 | 模型表现 |
|---|---|---|
| “Our engineers receive the revised requirements. From those edits they can pinpoint the checks that have to be repeated.” | 「需求变更后知道要重跑哪些测试」变灰 | 英文语义推断给出 90.4%，认出了跨句改述。 |
| “A person signs off on every release. Sharing one approved requirements document has cut the number of coordination calls.” | 两个已讲点变灰，中间遗漏的测试要点保持白色 | 对减少会议、定位测试和人工批准分别给出 91.7%、1.8%、90.6%。 |
| “Nothing goes out the door until a person has signed off on it.” | 「每次发布前都要有人批准」变灰 | 英文语义推断只给出 7.8%，逐要点具体选项给出 87.1%。 |
| “The target is to cut response time from eight seconds to three, but we have not achieved that yet.” | 「响应已从八秒降到三秒」保持白色 | 英文语义推断给出 67.9%，降低阈值会把目标标成成绩。 |
| 「大家现在都按同一份需求定稿办事。」 | 「统一需求减少协调会」保持白色 | 中文具体选项给「会议次数减少」92.9%。完整讲出这个因果关系时也只给了 81.7%。 |

## 速度和下一轮验收

本机英文 INT8 首次下载 85.6 秒，建推理会话 4.0 秒，预热 335 毫秒。随后英文通用语义推断单次只核实一个要点，75 次的模型时间中位 502 毫秒，P95 为 542 毫秒。一次提交三个手写选择题时，22 次的中位约 1.30 秒，P95 约 1.40 秒。中文在外部服务上验证语义，两种设备和运行方式的耗时不能合并。以上均不能推算现场从说完到变灰的实际延迟。

下一轮可保留 Laya 用于缩小候选范围，用已针对自然语言推断训练的本地模型与它做同题对照，首个候选为 mDeBERTa-v3-base-mnli-xnli。[候选模型与训练任务](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli)

值得首先盲测的是短改述、否定、缺少因果后半句、数字相同但含义不同、中文夹英文等反例。按胶片划分开发与留出材料，冻结阈值后同时报告各组误灰和召回。文本判定过关之后，再用 Apple 和 Whisper 重放同一录音，验证状态累积、问答冻结、翻页及真实延迟。

## 复核方法

本目录内运行 `python3 evaluate.py` 即可从逐条观测重算上表及延迟。英文评分与逐要点选择的题干、样本、预期和输出见 [questions](english-questions.json) 与 [English samples](english.tsv)。通用推断按「Premise: 发言」换行「Hypothesis: 讲稿要点」输入，英文每对独立请求。中文通用推断在题干前加样例编号以核对异步结果。[推断题干和中文选项](inference-questions.json) · [英文逐对概率与耗时](entailment.tsv) · [新要点](new-claims.tsv) · [中文逐对概率](chinese.tsv)

装有上游 Laya SDK 并已取得本地权重目录时，可运行 `python3 evaluate.py --replay /path/to/checkpoint --language en` 或 `--language zh`，逐条输出 SDK 的完整答案。这是供原生模型交叉复验的入口。上述英文数字来自浏览器实际运行，中文数字来自原版模型演示。不同权重、量化和输入格式需分别报告。[上游实现](https://github.com/NandhaKishorM/laya)

英文已有后续同题对照、跨胶片样本和合成语音测试。[FineCat 英文验证](../EnglishCoverage/README.md)
